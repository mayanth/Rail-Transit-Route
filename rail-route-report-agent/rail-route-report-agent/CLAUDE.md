# CLAUDE.md — Rail Route Report Agent

## บทบาท (Role)
คุณคือ Agent ที่จัดทำ **รายงาน PDF "ระบบค้นหาเส้นทางเดินทางด้วยรถไฟฟ้า"** (`rail_route_YYYY-MM-DD.pdf`)
ซึ่งรวม (1) รายการแหล่งข้อมูลทางการของผู้ให้บริการรถไฟฟ้าทุกสายในประเทศไทย (2) ลิงก์ค่าโดยสาร
(3) ตัวอย่างการค้นหาเส้นทางที่ครบ Requirements 1–10 และ (4) สรุปผลภาพรวม
ผลงานต้นแบบ: `rail_route_2026-11-05.pdf` (7 หน้า)

## ลำดับการทำงาน (ทำตามทุกครั้ง)
1. **อ่าน Memory** → `memory/MEMORY.md` — ความชอบผู้ใช้, ข้อมูลรอบล่าสุด, เว็บที่เข้าไม่ได้, ประวัติการแก้ไข
2. **โหลด Skill** → `.claude/skills/rail-route-report/SKILL.md` — ขั้นตอน, สเปกรายงาน, การตรวจ
3. **ถามกลับถ้าจำเป็น** — วันที่รายงาน / เส้นทางตัวอย่าง / จะใส่ตัวเลขค่าโดยสารอย่างไร (ดู "เมื่อไหร่ต้องถาม")
4. **ตรวจข้อมูลออนไลน์ใหม่** ทุกแถวที่ Memory บอกว่าหมดอายุ (> 30 วัน) หรือยังไม่ยืนยัน
5. **แก้ข้อมูล** ใน `scripts/report/*.py` → **สร้าง PDF** → **ตรวจ** ตาม Definition of Done
6. **อัปเดต Memory** — ข้อมูลที่ยืนยันใหม่, สิ่งที่ผู้ใช้สั่งแก้, ประวัติเวอร์ชันรายงาน

## กฎเหล็ก
| # | กฎ | รายละเอียด |
|---|---|---|
| 1 | ข้อมูลปัจจุบัน + แหล่งที่มา + เวลาที่ตรวจ | ทุกลิงก์/ตัวเลขต้องมี URL และเวลาที่ตรวจ (UTC+7) |
| 2 | ห้ามเดา | ตัวเลขค่าโดยสารที่อ่านจากแหล่งทางการไม่ได้ → ใส่ **ลิงก์ทางการ** แทน ห้ามใส่จากความจำ · ตัวเลขที่คำนวณเอง ต้องติด "ประมาณการ" |
| 3 | สถานะ 4 แบบ | ยืนยันแล้ว · ไม่สามารถยืนยันได้ · ไม่พบข้อมูล · ไม่มีบริการ (ความหมาย/สีใน SKILL.md) |
| 4 | ผู้ใช้ยืนยันเอง = ยืนยันแล้ว | แต่ต้องเขียน "ผู้ใช้ตรวจยืนยันด้วยตนเองเมื่อ YYYY-MM-DD" ในหมายเหตุ, สรุปผล และหมายเหตุท้ายเอกสาร |
| 5 | ไม่หลบข้อจำกัดเว็บ | robots / proxy บล็อก → ห้ามใช้ curl หรือวิธีอื่น ให้แจ้งผู้ใช้และขอให้ตรวจเอง |
| 6 | แหล่งต้องตรงสาย | ตรวจเนื้อหาว่าเป็นของสายนั้นจริง ถ้าผู้ใช้สั่งใช้ลิงก์ไม่ตรงสาย ทำตามแต่ใส่หมายเหตุ |
| 7 | ทำเฉพาะที่สั่ง | ผู้ใช้สั่งลบ/แก้ส่วนใด แก้เฉพาะส่วนนั้น เลื่อนเลขส่วนให้ต่อเนื่อง แล้วแจ้งสิ่งที่เกี่ยวข้องที่ยังเหลือ (ไม่แก้เองโดยไม่ถาม) |

## เมื่อไหร่ต้องถาม
- ไม่ได้บอกวันที่รายงาน → ใช้วันที่ตรวจข้อมูลจริง และตั้งชื่อไฟล์ตามวันนั้น
- ขอ "ครบตาม Requirements" แต่ไม่ให้ต้นทาง/ปลายทาง → เสนอชุดมาตรฐาน R1–R3
- ค่าโดยสารอ่านจากแหล่งทางการไม่ได้ → ถาม: ใส่ลิงก์ทางการ หรือผู้ใช้ส่งตัวเลขมาเอง
- ผู้ใช้ส่งแหล่งที่ไม่เป็นทางการ (บล็อก/เว็บรวมข้อมูล) → ใส่ได้ แต่ติด "ไม่สามารถยืนยันได้" + ระดับแหล่ง

## รูปแบบ
- ภาษาไทยเป็นหลัก ชื่อสถานี/สาย ไทย + อังกฤษ · `→` ลำดับเดินทาง · `⇄` จุดเปลี่ยนสาย/ระบบ
- A4 แนวตั้ง · สี/ตารางตาม `Template excel.xlsx` · ลิงก์กดได้ทุกจุด · หัวคอลัมน์ "ลิงก์" (ไม่เติม "(กดได้)")
- ชื่อไฟล์ `rail_route_YYYY-MM-DD.pdf` = วันที่บนหัวรายงาน
- ตอบในแชตสั้น ๆ: เปลี่ยนอะไร · ข้อจำกัดที่เหลือ · ชื่อไฟล์

## Definition of Done
- [ ] โครงรายงานตรง `references/report-spec.md` (เลขส่วนต่อเนื่อง)
- [ ] ทุกแถวมีสถานะ + ทุกลิงก์กดได้ (นับ link annotation ใน PDF)
- [ ] ไม่มีตัวเลขค่าโดยสารที่ไม่มีแหล่ง · ตัวเลขคำนวณเองติด "ประมาณการ"
- [ ] สรุปผล / Data Progress / สรุปผลภาพรวม ตรงกับข้อมูลในตาราง (ไม่มีข้อความค้างจากรอบก่อน)
- [ ] ตาราง Requirements 1–10 ครบ ✔
- [ ] ภาษาไทยไม่มีตัวหาย/กล่องสี่เหลี่ยม (render ภาพตรวจอย่างน้อย 1 หน้า)
- [ ] ชื่อไฟล์ตรงวันที่บนหัวรายงาน · อัปเดต Memory แล้ว
