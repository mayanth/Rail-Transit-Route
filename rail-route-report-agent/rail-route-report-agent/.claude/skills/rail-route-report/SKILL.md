# Rail Route Report Skill

## Workflow

### Step 0 — โหลดบริบท
- `memory/MEMORY.md` → ความชอบผู้ใช้ (§1), ข้อมูลรอบล่าสุด (§2), เว็บที่เข้าไม่ได้ (§3), ประวัติแก้ไข (§5)
- `references/report-spec.md` → โครงรายงานที่ต้องได้
- `references/sources.md` → URL ที่ต้องตรวจ

### Step 1 — ระบุงาน
| คำสั่งผู้ใช้ | ทำอะไร |
|---|---|
| สร้างรายงานใหม่ / อัปเดตประจำ | ตรวจทุก URL ใน sources.md → แก้ข้อมูล → สร้าง PDF ทั้งฉบับ |
| ใส่ลิงก์/ข้อมูลจาก URL ที่ให้มา | WebFetch URL นั้น → ตรวจว่าตรงสาย → ใส่ในช่องที่ระบุ |
| ลบ / แก้ข้อความ / เปลี่ยนสถานะ / เปลี่ยนชื่อไฟล์ | แก้เฉพาะที่สั่ง → ตรวจข้อความที่ได้รับผลกระทบ (สรุปผล, หมายเหตุ) |

### Step 2 — ตรวจข้อมูลออนไลน์
1. WebSearch ใช้ไม่ได้ในองค์กรนี้ → ใช้ **WebFetch** เปิด URL ทางการโดยตรง
2. ถามคำถามเจาะจงใน prompt ของ WebFetch เช่น "บริษัทอะไร เดินรถสายไหน ลิงก์ค่าโดยสาร" / "คัดลอกตารางค่าโดยสารตรงตัว บอกด้วยถ้าตัวเลขอยู่ในรูปภาพ"
3. ผลลัพธ์ที่เป็นไปได้ → สถานะ:

| ผลการเปิดเว็บ | สถานะ | ทำต่อ |
|---|---|---|
| เปิดได้ เป็นหน้าทางการของสายนั้น | ยืนยันแล้ว | บันทึก URL + เวลาที่ตรวจ |
| `robots_disallowed` / proxy 403 / `client_error` | ไม่สามารถยืนยันได้ | ใส่ URL ทางการ + เหตุผล → ขอให้ผู้ใช้ตรวจ |
| เปิดได้แต่ตัวเลขอยู่ในรูปภาพ/PDF/เครื่องคำนวณ | ไม่สามารถยืนยันได้ (ตัวเลข) | ใส่ลิงก์เอกสาร/เครื่องคำนวณแทนตัวเลข |
| แหล่งระดับ 3 (บล็อก, เว็บรวมข้อมูล, มีโฆษณา) | ไม่สามารถยืนยันได้ | ระบุ "แหล่งระดับ 3" แม้หลายแหล่งตรงกัน |
| ผู้ใช้ยืนยันเอง | ยืนยันแล้ว | หมายเหตุ "ผู้ใช้ตรวจยืนยันด้วยตนเองเมื่อ YYYY-MM-DD" |
| ยืนยันว่ายังไม่เปิด/ปิด | ไม่มีบริการ | ใส่ลิงก์หน้าโครงการ |

4. ตารางค่าโดยสารที่ได้ → ตรวจสมมาตร (A→B = B→A) และค่าต่ำสุด/สูงสุดก่อนใช้

### Step 3 — แก้ข้อมูลในสคริปต์
| ข้อมูล | ไฟล์ / ตัวแปร |
|---|---|
| สาย, ผู้ให้บริการ, ลิงก์เว็บ, ลิงก์ค่าโดยสาร, สถานะ, หมายเหตุ | `scripts/report/build_report.py` → `LINES` (tuple: สาย, ปลายสาย, ผู้ให้บริการ, เว็บ, ค่าโดยสาร, สถานะ, หมายเหตุ) |
| เวลาที่ตรวจหลัก | `CHECKED` · ค่าโดยสาร รฟม. `FARE_CHECKED` |
| ข้อบังคับค่าโดยสาร รฟม. / ส่วนลดเปลี่ยนถ่าย | `FARES`, `TRANSFER` |
| หน่วยงานรัฐ / สายที่ยังไม่เปิด | `AGENCIES`, `UPCOMING` |
| ตัวอย่างเส้นทาง + Requirements | `scripts/report/routes.py` → `ROUTES`, `REQS` |
| ค่าโดยสารสายสีแดง (R3) | `scripts/report/redline.py` → `RED_TABLES`, `RED_CHECKED` |
| สี | `scripts/build_pdf.py` → `XL`, `STATUS` |

กฎตอนแก้: ข้อความสรุปที่อ้างจำนวน (เช่น "BTS 3 สาย และ ARL ...") ต้องแก้ให้ตรงทุกครั้งที่สถานะเปลี่ยน

### Step 4 — สร้าง PDF
```bash
python .claude/skills/rail-route-report/scripts/report/build_report.py rail_route_YYYY-MM-DD.pdf
```
ต้องมี Playwright + Chromium (ฟอนต์ไทย Noto Sans Thai / Loma)

### Step 5 — ตรวจ (บังคับ)
```bash
pdfinfo rail_route_YYYY-MM-DD.pdf | grep Pages
pdftotext rail_route_YYYY-MM-DD.pdf - | grep -n -E "^[0-9]\. "          # เลขส่วนต่อเนื่อง
python -c "import pypdf;r=pypdf.PdfReader('rail_route_YYYY-MM-DD.pdf');print(sum(1 for p in r.pages for a in (p.get('/Annots') or []) if a.get_object().get('/A')))"  # จำนวนลิงก์
pdftoppm -r 70 -png rail_route_YYYY-MM-DD.pdf page                        # เปิดดูภาพ
```
ตรวจตาม Definition of Done ใน CLAUDE.md และ `references/pdf-criteria.md`

### Step 6 — รายงานผล + อัปเดต Memory
- แชต: เปลี่ยนอะไร (1–3 ข้อ) · ข้อจำกัด/สิ่งที่ยังเหลือที่ผู้ใช้อาจต้องการแก้ · ชื่อไฟล์
- Memory: §2 ข้อมูลใหม่ + เวลา · §5 บันทึกการแก้ไขรอบนี้ · §1 ถ้าผู้ใช้แสดงความชอบใหม่

## สถานะและสี (ตาม Template excel)
| สถานะ | ความหมาย | ตัวอักษร / พื้น | เทียบ Template |
|---|---|---|---|
| ยืนยันแล้ว | แหล่งระดับ 1–2 หรือผู้ใช้ยืนยันเอง | `#006100` / `#C6EFCE` | PASSED |
| ไม่สามารถยืนยันได้ | แหล่งไม่ทางการ / ขัดกัน / อ่านไม่ได้ | `#9C5700` / `#FFEB9C` | Need confirmation |
| ไม่พบข้อมูล | ค้นแล้วไม่เจอ | `#404040` / `#D9D9D9` | SKIPPED |
| ไม่มีบริการ | ปิด / ยังไม่เปิด | `#9C0006` / `#FFC7CE` | BLOCKED |
| ⭐ แนะนำ | เส้นทางที่แนะนำ | แถวฟ้า `#A6C9EB` ตัวหนา | แถวกลุ่ม |

## ตัวอย่างเส้นทางมาตรฐาน (ส่วนที่ 5)
| รหัส | เส้นทาง | ทางเลือก | Requirements ที่ครอบคลุม |
|---|---|---|---|
| R1 | อโศก → หมอชิต | ⭐ BTS สุขุมวิท 11 สถานี 0 เปลี่ยน · MRT สุขุมวิท→สวนจตุจักร 9 สถานี (เดินเชื่อม 2 ช่วง) | 1–3, 5–8, 9 |
| R2 | พระราม 9 → สยาม | ⭐ MRT→สุขุมวิท ⇄ BTS อโศก→สยาม (2+4) · MRT→สีลม ⇄ ศาลาแดง→สยาม (6+2) · MRT→เพชรบุรี ⇄ ARL มักกะสัน→พญาไท ⇄ BTS→สยาม (1+2+2) | 4, 5, 8, 9 |
| R3 | กรุงเทพอภิวัฒน์ → ดอนเมือง | ⭐ สายสีแดงเข้ม 7 สถานี — 33 / 30 / 17 บาท | 7 (ตัวเลขจริงแยกประเภทบัตร) |

- จำนวนสถานี = จำนวนสถานีที่ผ่านจนถึงปลายทาง (ไม่นับต้นทาง) · นับทีละสถานี
- เวลา = ประมาณการ ~2 นาที/สถานี + รอ/เดินเปลี่ยนระบบ (ติด "ไม่สามารถยืนยันได้")
- ทิศทางสายสีน้ำเงินไม่แน่ใจ → "ตรวจป้ายปลายทางที่ชานชาลา"
- จุดเปลี่ยนระบบทุกจุดต้องมีกล่อง ⚠️: แตะบัตรออก → เดินเชื่อม → แตะบัตรใหม่ → ค่าโดยสารคิดแยก

## ข้อผิดพลาดที่เคยเกิด (ห้ามซ้ำ)
- ใช้ srtet.co.th/fare-information เป็นค่าโดยสาร ARL — เป็นของ **สายสีแดง**
- ข้อความสรุปค้างจากรอบก่อน หลังเปลี่ยนสถานะ (เช่น ยังเขียนว่า "4 สายยังไม่ยืนยัน")
- เลขส่วนไม่ต่อเนื่องหลังลบส่วน
- คิดว่า BEM Fare-Calculation ครอบคลุมสายสีเหลือง/ชมพู (EBM/NBM มีเครื่องคำนวณเอง) — ถ้าผู้ใช้สั่ง ให้ทำ + แจ้ง
- นับสถานีอโศก→หมอชิตผิด (ที่ถูก 11)
